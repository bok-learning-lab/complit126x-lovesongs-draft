# Three Ways to Complete the Assignment

You've seen what happens when you generate lyrics from scores alone, and in the workshop you practiced building a chain that does better — one-shotting a sonnet, diagnosing it, having a dialogue with the model, identifying atomic mechanics, and assembling a sequence. Now you need to do the same thing for your poet and your love song.

Here are three ways to do that, from simplest to most involved. Pick the one that matches your comfort level and ambition.

---

## Option 1: Conversational Chat

**Best for:** Getting started quickly, or if you want to focus on the writing rather than the code.

You already did this in the workshop. You built a prompt chain in a chat window — no code required. The assignment works the same way: do it in stages, in any chat interface (Gemini, Claude, ChatGPT), saving each step's output before moving to the next.

The difference between the workshop and the assignment is **documentation**. In the workshop, you worked collaboratively and presented your chain on paper. For the assignment, you need to keep a log of:

- **What you did at each step** — the actual prompts you used
- **Why you made each choice** — what you were trying to get the model to do, and what you noticed
- **What changed** — how the output improved (or didn't) from one step to the next

Think of it as the paper-and-index-card version of your workshop sequence, but written up. The [Workshop](/reading/prompt-chaining-guide#the-workshop-activity) recap has the full activity flow if you want a refresher.

Here's one possible sequence (adapt it — your chain should reflect your poet):

1. **Paste each poem** and ask the model to score it on your traits (same as the web tool). Note the scores.
2. For each poem, ask: *"Extract the 3–5 most characteristic phrases from this poem. Describe its formal moves, emotional arc, and recurring sounds. Be specific and quote the text."*
3. Once you have 3+ poems analyzed, paste all the texture analyses together and ask: *"Synthesize a 150-word voice profile for this poet from these analyses."*
4. Finally, paste the voice profile + scores and ask: *"Write a love song in this poet's style."*
5. Refine: paste the draft back and add specific feedback — *"The chorus is too abstract. Revise with a concrete image from the poems."*

**For your essay:** Save your prompts at each step. You'll need to include them and explain why you made each choice.

## Option 2: Python Notebooks

**Best for:** Students who want a structured, reproducible workflow — or who want to build on what their group did in the workshop.

If you did the **Ancient Robots** section work, you already have everything you need: your OpenAI API key is already set up in Colab Secrets, and you've used the same `client.responses.create()` pattern before. These notebooks use the same key and the same SDK — just a different task.

#### Adding the notebook to your course folder in Google Drive

1. Click the download link above — the file `complit126x-love-songs.ipynb` will save to your Downloads folder.
2. Go to [drive.google.com](https://drive.google.com) and navigate to your **complit126x** folder.
3. Click **New → File upload** and select the downloaded `.ipynb` file.
4. Double-click the uploaded file — it will open in **Google Colab**.
5. In Colab, click the **🔑 Secrets** icon in the left sidebar. Your `OPENAI_API_KEY` should already be there from the Ancient Robots workshop — just make sure **Notebook access** is toggled ON. If you need to add it fresh, paste in your OpenAI key.
6. Run the cells from top to bottom. The first cell installs the required package.

**What's in the notebook:**
- Step 0: Define your traits
- Step 1: Add a poem → analyze → extract texture → save to pool *(repeat for each poem)*
- Step 2: Synthesize a voice profile across your poem pool
- Step 3: Generate lyrics with the full chain
- Step 4: Generate from scores only — compare the two outputs
- Going Further: experiments to try, submission checklist

### Workshop Notebooks by Poet

These notebooks are built from the prompt chains your groups designed in the workshop — translated from your paper diagrams and presentation transcripts into runnable Python. Each one implements the specific sequence of operations your group discovered, so the chains differ from poet to poet.

You can use your group's notebook as a starting point for the assignment, modify it for a different poet, or use it as inspiration for building your own chain.

**A note on models:** Several groups used multiple models in the workshop (Gemini, Claude, ChatGPT) — for example, generating in one and critiquing in another. These notebooks use the **OpenAI API only** (GPT-4o), since that's what your API keys support. The chain logic is the same; where a group originally switched models, the notebook simulates the "fresh perspective" by opening a new API call with a different system prompt or by stripping prior context. The architecture matters more than which model runs each step.
